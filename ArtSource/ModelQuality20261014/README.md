# 모델 보정 작업 원본

현재 Investigation 씬에서 사용하는 모델을 대상으로 한 보정 작업이다. `inventory.json`은 작업 시작 때의 대상 목록이며, 목록에 있다는 이유만으로 수정 완료된 것은 아니다.

- `Input/`: Unity의 실제 사용 메시·UV·원본 재질 경로·미터 단위 작업 좌표 변환. 최초 입력은 재실행으로 덮어쓰지 않는다.
- `<모델>.blend`: 원본 메시와 보정 메시를 함께 보관하는 편집 파일. 같은 Blender 창의 개별 작업 씬에서 제작한다.
- `Textures/`: Unity 내부 생성 텍스처를 Blender에서 읽도록 내보낸 사본. 기존 텍스처는 유지한다.
- 게임 출력: `Assets/Art/ModelQuality20261014/<모델>/`. 기존 메시를 수정하지 않고 별도 메시·재질로 씬에 연결한다.

## 작업과 확인

기존 Blender의 `Tools/blender_work_session.py` 연결을 사용한다. `Tools/request_blender_job.py refine_prop --prop <Input 파일 이름>`으로 하나만 요청하고 완료 로그와 렌더를 확인한 뒤 다음 모델로 넘어간다. 새 Blender나 백그라운드 프로세스를 실행하지 않는다. 완성 파일이 이미 있으면 작업을 중단한다.

인물은 기존 정점 순서·UV·손목 경계·노멀·리그·손가락 모양 키를 보존한다. 옷과 볼의 작은 표면 요철을 제한적으로 완화하며, 이것만으로 해부학적 조형이나 얼굴의 근접 품질이 완성됐다고 보지 않는다. 몸 2K, 손 1K로 색상·노멀·AO·금속/매끄러움을 굽는다. Cycles 8 샘플, 패딩 12픽셀을 사용한다. 색상에는 조명을 굽지 않는다.

배경 도구는 원본 재질과 UV를 남기고 게임용 UV를 별도로 만든다. 단단한 가구 모서리는 최대 2.5mm 범위에서 다듬는다. 바닥과 천막 입구를 임의로 이동하지 않는다. 게임용 메시를 교체할 때 기존 충돌체와 조사 대상을 유지한다.

`Logs/ModelQuality/reviewed.txt`는 로컬 검토를 통과한 개별 모델 목록이다. Unity의 `Tools/Model Quality/Apply Reviewed Models`는 이 목록만 적용하고 씬 사본을 먼저 저장한다. `Review Applied Models`의 화면과 격리 Play의 대기·손목 검사를 함께 확인한다. 자동 검사 통과와 시각 품질 판정은 구분한다.

신규 파일은 일반 Git으로 관리한다. `.blend1`·실패한 중간 출력·검토 렌더는 Git 대상이 아니다. 50MiB 제한과 LFS 포인터 검사는 `Tools/check-staged-files.sh`에서 시행한다. 이 문서 작성 시점에는 전체 모델 보정이 진행 중이며 전체 완료를 뜻하지 않는다.


## 2026-10-14 적용 범위
인물 몸·손 30개, 손에 든 문서 3개, 환경 메시 55개를 보정·베이킹해 씬에 연결했다. 입력의 Zhangyun_Body는 UV 수정본 Zhangyun_BodyMaterialFix로 대체됐다. 면이 없는 지도 잉크 메시와 Unity 기본 도형으로 만든 구조물 273개는 수정 완료 수에 포함하지 않는다. 기존 VARCO 상세 소품 6종은 별도 ArtSource/VarcoDetail20261014에서 관리한다.

편집 파일은 정적인 표면·메시 작업 원본이다. 인물의 리그·모양 키·애니메이션 원본은 기존 Unity 자산에 남아 있으며 설치 도구가 복제·보존한다. 천막과 지면 등은 원래 UV 반복을 유지하는 1K 재질 단위 베이킹을 사용한다.

가구 최대 2.5mm 모서리 보정과 표면 정리는 1차 보정이다. 배의 단순한 선체, 천막 주름, 포대의 찢어진 형상, 인물 얼굴과 손의 근접 조형은 출시 전 추가 검토가 필요하다. 모든 모델의 상용화 품질을 보증하는 완료 표시는 하지 않는다.

현재 작업 창 전체 스냅샷은 Git에서 제외된 Logs/ModelQuality/WorkingSession-20261014-140121.blend에 있다. 인계에는 모델별 .blend와 입력·텍스처·제작 도구를 사용한다.
