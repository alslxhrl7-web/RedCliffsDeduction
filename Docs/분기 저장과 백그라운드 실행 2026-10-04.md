# 분기 저장과 백그라운드 실행

## 동작

- PlayerSettings의 `runInBackground`와 런타임 `Application.runInBackground`를 활성화했다. 창을 벗어날 때 자동으로 일시정지 화면을 열던 동작을 없앴다. 입력은 창이 활성화됐을 때만 처리하고, 배경음과 날짜 연출은 계속 진행한다.
- 선택 화면에서 F5 또는 Esc 메뉴의 저장 / 불러오기로 수동 슬롯 1~3을 고른다. 기존 파일이 있으면 저장 내용 확인 후 덮어쓴다. 자동저장은 수동 슬롯을 덮어쓰지 않는다.
- F9 또는 저장 메뉴에서 수동 슬롯과 최근 자동저장을 선택해 불러온다. 시작 화면의 기존 불러오기 버튼도 같은 슬롯 선택기로 연결했다.
- 수동 저장은 진행 중인 문장이나 날짜 연출을 중단하지 않도록 대화 완료 후 선택 화면에서 수행한다. 키 안내는 분기 화면 하단에 표시한다.
- 인물 질문·조사 선택·자료 대조·이동·날짜 일정·최종 보고 선택 등 저장한 분기의 선택 화면을 다시 연다. 결과 설명의 개별 문장·스크롤 위치·플레이어 좌표는 저장하지 않고, 해당 조사 선택 화면과 장소 입구로 복원한다. 이미 소비한 조사 횟수와 확보한 기록은 그대로 유지한다.
- 최종 보고 중 지목 대상, 확정 여부, 제출 근거, 후속 요청 및 기한 잠금도 복원한다. 보고 완료 이후 엔딩 저장은 이번 범위에 넣지 않았다.

## 자동저장

각 프레임 끝에 조사 횟수·증거·진술·분기·보고 선택 상태의 변경을 비교해 변경됐을 때만 저장한다. 저장 성공 확인창으로 다음 행동을 가로막지 않는다. 조사 시작 시 차감된 횟수도 보관하므로 도중에 다시 불러와도 같은 주제에 추가 비용을 쓰지 않는다. 중단된 대화는 해당 인물의 질문 선택 화면에서 다시 확인한다.

종료·앱 일시중단 시에도 저장을 시도한다. 자동저장 실패는 콘솔과 하단 안내에 표시하며 같은 실패 상태로 매 프레임 반복 기록하지 않는다. 이후 상태 변경에는 다시 시도한다. 실패 시 다음 행동 자체는 계속할 수 있다.

## 파일과 호환성

`Application.persistentDataPath` 아래에 다음 파일을 사용한다.

- 수동 슬롯 1: 기존 `investigation-save.json`
- 수동 슬롯 2~3: `investigation-save-2.json`, `investigation-save-3.json`
- 최근 자동저장: `investigation-autosave.json`

기존 version 1 저장에 선택 지점과 보고 상태를 선택 항목으로 추가했다. 이전 파일에 선택 지점이 없으면 기존처럼 조사 장소로 돌아온다. 임시 파일 검증 후 교체하고 기존 파일은 `.bak`으로 보존하는 방식을 유지했다. 알 수 없는 선택 지점과 손상된 보고 선택은 불러오기 전에 거부한다.

## 확인 범위

후속 빌드·실행 요청에서 Unity 직렬화의 빈 보고 객체로 인한 자동저장 오류를 수정했다. 실제 Unity 저장 검사와 Windows 빌드, 문서고 자동저장 및 재실행 후 불러오기가 통과했다. 최신 확인 범위와 남은 렌더링 경고는 `빌드 실행 검증 2026-10-04.md`에 기록했다.

이후 점검에서 조사 시작 전 F9 취소 복귀 문제와 저장 검사 도구의 메뉴 종료 순서를 수정했다. 최신 C# 별도 컴파일과 순수 로직 검사는 통과했다. 실제 Unity Play·빌드·저장 파일 왕복은 실행하지 않았다. 자세한 결과는 `적용 내용 점검 2026-10-04.md`에 기록했다. 아래는 최초 구현 시 확인 범위다.

저장 경로 분리, 분기 재진입 연결, 포커스 입력 처리, 기존 저장 호환 조건 및 변경 차이를 코드로 확인했다. `InvestigationSaveChecks`에 보고 분기 왕복, 잘못된 분기 거부 및 슬롯 경로 검사 항목을 추가했지만 실행하지 않았다. Unity Play·빌드 및 실제 저장/불러오기 완주 검증은 하지 않았다.

이전 URP 셰이더 복구는 별개로 열린 편집기에서 실행됐으며 현재 셰이더 메시지 오류 0건 결과가 `URP 셰이더 복구 결과 2026-10-04.md`에 남아 있다.
