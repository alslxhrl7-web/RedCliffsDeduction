# 베이킹 문제

베이킹과 내보내기 과정에서 실제 발생한 문제만 관리한다. 원본 모델의 손가락 결합 등 조형 문제는 이 문서의 베이킹 오류와 구분한다.

| 문제 | 원인 | 처리·현재 상태 | 재발 방지 |
|---|---|---|---|
| 손 거칠기 맵을 Unity용 매끄러움 채널로 변환하다 중단 | Blender 픽셀 버퍼에 64비트 NumPy 배열을 전달해 타입 오류 발생 | 32비트 실수 배열로 변환한 뒤 색상·노멀·마스크 60장을 다시 생성 | 이미지 픽셀 전달 형식을 float32로 고정하고 생성된 PNG와 전송 자료를 검사 |
| 새 손이 Unity에서 어둡거나 안쪽 면처럼 보임 | 기존 몸체에서 사용하던 삼각형 반전 규칙을 자체 제작 손에도 적용함 | 새 손은 바깥 방향의 삼각형 순서를 유지하도록 내보내기를 수정. 적용 도구에서도 면 방향과 노멀의 일치를 검사 | 새 메시와 기존 메시의 변환 규칙을 구분하고 Blender 미리보기 외에 Unity 실행 화면까지 확인 |
| 새 손의 베이크 색이 지나치게 밝고 창백함 | 텍스처에서 뽑은 sRGB 색을 선형 셰이더 색으로 그대로 넣음 | sRGB→선형 변환 후 다시 베이킹해 수정 | build_hands.py에서 피부 샘플 색을 변환하고 기존 얼굴·손목과 비교 |
| 새 천막이 검거나 금속처럼 보임 | Blender에서 메시를 합친 뒤 기존 UVMap이 남아, Unity가 BakeUV 대신 첫 UV 채널을 사용함 | 게임용 메시에는 BakeUV만 남겨 다시 내보냄. Unity 실행 화면에서 정상 재질 확인 | build_environment.py에서 BakeUV 외 UV를 내보내기 전에 제거. 편집용 원본 UV는 별도로 보존 |
| 인물 동작 적용 후 얼굴·표면의 노멀 방향이 어색함 | Blender와 Unity의 삼각형·표면 방향 변환이 맞지 않음 | 역할 자세의 노멀 변환을 수정했고 인물 10명 연결·노멀 검사 통과 | 위치와 노멀의 좌표 변환을 함께 검사. 원래 메시 노멀과 내적 검사 유지 |
| Blender 저장 시 썸네일 파일 쓰기 실패 | 사용자 .thumbnails/large 경로에 미리보기 PNG를 쓸 수 없었음 | .blend 저장과 베이크 PNG·동작 출력은 완료. 운영체제 썸네일 생성만 실패한 상태 | 베이크 완료 로그와 실제 출력 파일을 따로 확인. 썸네일 오류만 보고 본 작업 실패로 판단하지 않음 |
| 얼굴 색상 보정을 반복하면 대비가 계속 약해질 위험 | 이미 보정·베이킹한 텍스처를 다시 입력으로 사용하면 누적 처리됨 | 아직 발생한 품질 사고는 아니며 검사 중 발견한 재실행 위험. 중복 베이킹 감지 시 중단하도록 보호 | build_detail.py로 원본에서 재생성한 다음 bake_face.py 실행. 수작업 원본은 별도 보존 |

## 확인 자료
- 배경 베이크·내보내기: Logs/EnvironmentRefresh/blender-bake.txt, fix-uv.txt, final-play-*.png
- 인물 보정·얼굴 베이크: Logs/CharacterDetail/build.txt, face-bake.txt
- 인물 노멀·연결: Logs/RoleActivities/validation.txt

로그와 검토 이미지는 로컬 확인 자료로 보관하고 Git에 올리지 않는다. 새 문제가 실제 발생하면 상태를 추가·갱신한다.


## 2026-10-14 — 군기 제작
- 창이 보이는 Blender에서 factory reset 직후 USD 가져오기가 context 오류로 중단됐다. 새 작업 창에서 기본 객체만 초기화하도록 바꿔 해결했다.
- 한국어 Blender의 노드 표시 이름 때문에 Principled BSDF 조회가 실패했다. 표시 문자열 대신 노드 타입으로 찾아 해결했다.
- 새 목재 재질의 Generated 좌표가 기존 USD용 SourceUV 고정 처리에 덮여 나뭇결이 단색처럼 구워졌다. 새 제작 부품은 원래 좌표 연결을 유지하게 분리하고 다시 베이킹했다.
- 바르코 HTTP 500은 파일 전송 단계 오류이며 베이킹 오류와 별개다. 이후 기존 Blender 창으로 직접 전송을 확인했고 네 소품의 입력 파일을 확보했다.

## 2026-10-14 — 소품 매끄러움 맵과 인물 좌표
- 천막·목재의 UV 바깥 픽셀이 거칠기 0으로 구워져 매끄러움 1로 변환됐다. 밉맵 경계에서 번쩍일 수 있어 빈 영역을 포함해 매끄러움을 0.28 이하로 제한하고 천막·포대·책상·선반을 다시 구웠다.
- 인물 메시의 로컬 좌표는 미터 단위의 직립 좌표가 아니었다. 첫 시험 결과는 게임에 적용하지 않고 Logs/ModelQuality에 보관했다. 인물 루트 기준 변환 행렬을 내보내 실제 크기에서 보정하고, 결과를 원래 로컬 좌표로 돌려주도록 수정했다.
- 좌표 변환의 행렬식과 원본 노멀을 검사한다. 단순 회전에 삼각형 반전을 추가하지 않으며, 최종 적용 전 원본 노멀과의 일치를 확인한다.
- 한국어 Blender의 Background 표시 이름 조회로 검토 렌더가 중단됐다. 표시 이름 대신 노드 타입으로 찾도록 고쳤다.
- 장윤의 두 재질이 같은 UV 영역을 사용해 통합 텍스처에 옷과 얼굴 색이 겹쳤다. 재질별 텍스처로 분리해 다시 구웠고 Unity에서 정상 표시를 확인했다. 인물은 재질이 둘 이상이면 별도 베이크 타깃을 사용한다.
- 베이크 이후 Unity 메시를 만들면서 일부 인물의 인덱스 형식 변경으로 삼각형이 사라졌다. 원본 형식을 보존하고 기존 결과를 복구했다. 베이킹 자체의 실패와 구분하며, 적용 시 정점 수뿐 아니라 삼각형 배열·서브메시 수·모양 키 수를 검사한다.


## 2026-10-14 환경 표면 보정
- 면이 없는 `Tent_MapInk_WithoutDesk` 메시에서 UV 펼치기가 실패했다. 원본은 보존하고 베이킹 대상에서 제외했으며, 입력 단계에서 면 유무를 검사한다.
- 창의 둥근 부품을 전체 스무딩하면 끝면이 어둡게 보였다. 옆면과 끝면의 노멀 경계를 50도 기준으로 분리하고 창대·묶음 부품을 다시 구웠다.
- 넓은 바닥과 천막을 하나의 1K 아틀라스로 만들면 텍스처 밀도가 낮아진다. 반복 무늬 한 단위만 굽고 원래 UV 반복을 유지했다. 이 방식의 AO는 중립 값이며 큰 구조물의 차폐는 Unity 조명에 맡긴다.


## 2026-10-14 기본 도형 교체 키트
- 목패의 구멍을 Boolean으로 뚫은 뒤 빈 재질 슬롯이 남아 베이킹 재질 순회가 중단됐다. 게임용 결합 메시의 빈 슬롯을 목재로 채우고 다시 베이킹해 해결했다. 편집 원본의 개별 부품은 유지한다.
- 등불 베이크는 정상이었지만 Unity에서 복제한 임시 재질의 Unlit 셰이더와 EmissiveIsBlack 플래그 때문에 발광이 적용되지 않았다. URP Lit와 발광 플래그를 명시하고 종이 부분의 Emission 마스크가 실제 씬에서 빛나는 것을 확인했다. 이는 베이킹 이후 재질 연결 문제다.
