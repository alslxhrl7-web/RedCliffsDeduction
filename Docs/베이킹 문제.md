# 베이킹 문제

베이킹과 내보내기 과정에서 실제 발생한 문제만 관리한다. 원본 모델의 손가락 결합 등 조형 문제는 이 문서의 베이킹 오류와 구분한다.

| 문제 | 원인 | 처리·현재 상태 | 재발 방지 |
|---|---|---|---|
| 손 거칠기 맵을 Unity용 매끄러움 채널로 변환하다 중단 | Blender 픽셀 버퍼에 64비트 NumPy 배열을 전달해 타입 오류 발생 | 32비트 실수 배열로 변환한 뒤 색상·노멀·마스크 60장을 다시 생성 | 이미지 픽셀 전달 형식을 float32로 고정하고 생성된 PNG와 전송 자료를 검사 |
| 새 손이 Unity에서 어둡거나 안쪽 면처럼 보임 | 기존 몸체에서 사용하던 삼각형 반전 규칙을 자체 제작 손에도 적용함 | 새 손은 바깥 방향의 삼각형 순서를 유지하도록 내보내기를 수정. 적용 도구에서도 면 방향과 노멀의 일치를 검사 | 새 메시와 기존 메시의 변환 규칙을 구분하고 Blender 미리보기 외에 Unity 실행 화면까지 확인 |
| 새 손의 베이크 색이 지나치게 밝고 창백함 | 텍스처에서 뽑은 sRGB 색을 선형 셰이더 색으로 그대로 넣음 | sRGB→선형 변환 후 다시 베이킹해 수정 | build_hands.py에서 피부 샘플 색을 변환하고 기존 얼굴·손목과 비교 |
| 새 천막이 검거나 금속처럼 보임 | Blender에서 메시를 합친 뒤 기존 UVMap이 남아, Unity가 BakeUV 대신 첫 UV 채널을 사용함 | 게임용 메시에는 BakeUV만 남겨 다시 내보냄. Unity 실행 화면에서 정상 재질 확인 | build_environment.py에서 BakeUV 외 UV를 내보내기 전에 제거. 편집용 원본 UV는 별도로 보존 |
| 인물 동작 적용 후 얼굴·표면의 노멀 방향이 어색함 | Blender와 Unity의 삼각형·표면 방향 변환이 맞지 않음 | 역할 자세의 노멀 변환을 수정했고 인물 10명 연결·노멀 검사 통과 | 위치와 노멀의 좌표 변환을 함께 검사. 원래 메시 노멀과 내적 검사 유지 |
| Blender 저장 시 썸네일 파일 쓰기 실패 | 사용자 .thumbnails/large 경로에 미리보기 PNG를 쓸 수 없었음 | .blend 저장과 베이크 PNG·동작 출력은 완료. 운영체제 썸네일 생성만 실패한 상태 | 베이크 완료 로그와 실제 출력 파일을 따로 확인. 썸네일 오류만 보고 본 작업 실패로 판단하지 않음 |
| 얼굴 색상 보정을 반복하면 대비가 계속 약해질 위험 | 이미 보정·베이킹한 텍스처를 다시 입력으로 사용하면 누적 처리됨 | 아직 발생한 품질 사고는 아니며 검사 중 발견한 재실행 위험. 중복 베이킹 감지 시 중단하도록 보호 | build_detail.py로 원본에서 재생성한 다음 bake_face.py 실행. 수작업 원본은 별도 보존 |
