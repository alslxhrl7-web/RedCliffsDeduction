- 앱 내부 `/feedback`을 제출한 것은 아니며, 별도의 피드백 세션 ID는 없다.

## 제목

전역 사이트 허용 후에도 현재 대화의 저장된 거부가 유지되어 내장 브라우저 접근 불가

## 환경

- Windows, Codex 데스크톱 앱. 로컬 런타임 설정에 기록된 앱 버전: 26.930.31730.
- 발생일: 2026-10-04, 한국 시간.
- 대상 사이트: https://3d.varco.ai/explore
- 대화 ID: 01a10217-f98e-7072-b7ef-2594e06dbc28

## 재현 및 실제 동작

1. 내장 브라우저에서 대상 사이트에 에이전트가 접근할 때 초기 요청을 거부함.
2. 이후 설정의 에이전트 권한에서 https://3d.varco.ai 사이트 접근을 항상 허용으로 변경함.
3. 설정 화면에서 허용을 확인하고 앱을 재시작한 후, 같은 대화에서 열린 탭 연결을 다시 요청함.
4. `cua.getTab({ url: "https://3d.varco.ai/explore" }, { browser: "iab" })`가 계속 다음 오류를 반환함.

```text
Browser Use rejected this action due to browser security policy.
Reason: A saved user permission setting blocks this action.
Browser use cannot access https://3d.varco.ai because the user has a saved preference that blocks it.
```

## 기대 동작

사용자가 허용으로 변경하면 현재 대화에도 허용이 반영되거나, 대화별 거부가 별도로 남아 있음을 설정 화면에서 명시하고 정상적으로 해제할 방법을 제공해야 함.

## 읽기 전용 진단으로 확인한 근거

- `~/.codex/config.toml`의 `[browser_use.origins."https://3d.varco.ai"]`: `access = "allow"`.
- `~/.codex/browser/config.toml`의 `[origins]`: `allowed`에 대상 사이트 포함, `denied = []`.
- `~/.codex/browser/sessions/01a10217-f98e-7072-b7ef-2594e06dbc28.toml`의 `[origins].denied`: 대상 사이트가 여전히 포함됨.
- 설치된 브라우저 서비스는 대화별 거부가 있으면 전역 허용보다 먼저 `decision: "deny", scope: "conversation", source: "browser-use-persisted-state"`를 반환함. 실제 오류 분류는 `persisted_user_denied`.

## 요청

현재 대화의 거부를 정상적인 사용자 권한 관리 절차로 해제할 방법과, 전역 허용 변경이 기존 대화에 반영되지 않는 동작이 의도인지 버그인지 확인해 주세요.

권한 파일을 수정하거나 브라우저 보안 검사를 우회하지 않았습니다. 전체 사용자 설정·인증 정보·쿠키·다른 대화 내용은 신고 자료에 포함하지 않았습니다.

## 신고 시 첨부할 자료

- 에이전트 권한에서 https://3d.varco.ai가 항상 허용으로 표시된 사용자 캡처.
- 위 오류 원문 및 세 가지 설정의 해당 사이트 항목만.
- 전체 설정 파일 또는 인증·브라우저 프로필 자료는 첨부하지 않음.
