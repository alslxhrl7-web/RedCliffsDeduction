# 테스트 데모 0.1.0-demo.1

2026-10-02에 Windows 64비트용 실행 파일을 만들었다. 현재 Investigation 씬의 도입, 조사, 최종 보고와 모든 엔딩을 포함한다. 별도의 이야기 분기나 조사 비용 변경은 없다.

## 실행과 배포

- 배포 폴더: 상위 작업 폴더의 `산출물/RedCliffsDeduction_TestDemo_v0.1.0`.
- ZIP을 폴더째 압축 해제한 뒤 `RedCliffsDeduction.exe`를 실행한다. 실행 파일과 Data 폴더, DLL 및 런타임 폴더를 함께 배포한다.
- 기본 화면은 크기 조절이 가능한 1280×720 창 모드다.
- 플레이어용 설명은 `먼저 읽어주세요.txt`, 피드백 양식은 `테스트 의견.txt`에 있다. 정답이나 범인의 정체는 쓰지 않았다.
- 종료는 창의 닫기 버튼 또는 Alt+F4를 사용한다. 자동 저장은 없으므로 조사 중 메뉴에서 먼저 저장한다.

## 저장 분리

빌드할 때만 제품 이름을 `RedCliffsDeduction Test Demo`로 지정한다. 저장 위치는 `%USERPROFILE%/AppData/LocalLow/DefaultCompany/RedCliffsDeduction Test Demo`다. 개발 프로젝트의 저장 파일과 분리되며 기존 저장 파일을 복사하거나 지우지 않는다.

## 다시 빌드하기

Unity 6000.6.0f1과 Windows 빌드 지원을 사용한다. 프로젝트가 다른 Unity Editor에서 열려 있지 않은 상태에서 다음 명령을 실행한다. 출력 경로는 새 폴더로 정한다.

```powershell
unity build "프로젝트의 절대 경로" --target StandaloneWindows64 --execute-method TestDemoBuild.BuildWindows --output-path "출력 폴더의 절대 경로/RedCliffsDeduction.exe" --allow-dirty-build --no-tail
```

`Assets/Editor/TestDemoBuild.cs`는 엔딩·조사 횟수·저장 데이터 검사를 먼저 실행한다. 일반 배포 빌드이며 Development Build와 원격 코드 실행 서버를 켜지 않는다. 제품명·버전·화면 설정은 빌드 후 원래 값으로 되돌린다. Unity가 생성하는 그래픽 캐시 설정 변경은 별도로 검토한다.

`BackUpThisFolder_ButDontShipItWithYourGame` 폴더는 개발용 심볼 백업이므로 배포 ZIP에서 제외한다. 이번 백업은 작업 폴더의 `local-backups/TestDemo_v0.1.0_symbols`에 보관했다.

## 확인 범위

- Windows 빌드 성공, BuildReport 오류 0개.
- 엔딩 조건 24개 조합, 12회 비용 및 기한 판정, 저장·복원·한글 이름·덮어쓰기·백업·손상 기록 거부 검사 통과.
- 별도 실행 파일을 1280×720, 1920×1080 옵션으로 백그라운드 실행해 초기 로딩과 프로세스 응답을 확인했다. 관리 코드 예외나 충돌 기록은 없었다. 이는 실제 마우스·키보드 플레이나 화면 배치 검사를 대신하지 않는다.
- 1920×1080 검사 종료 전 로그에 Unity 내부 임시 메모리 수명 경고가 2회 있었다. 프로세스는 응답했으나 원인은 확인하지 않았으므로 실제 플레이에서도 재발하는지 살펴본다.
- 기존 Play 모드 검증은 `플레이 검증 결과 2026-10-01.md`를 참고한다. 이번 배포본의 전체 수동 플레이와 첫 사용자 난이도 평가는 남아 있다.
- 일부 임시 외형과 기존 추가 광원 그림자 품질 경고는 이번 빌드에서 수정하지 않았다.

배포 ZIP은 약 85.2MiB, 압축 해제 후 약 147.5MiB이며 파일 188개의 압축 무결성을 확인했다. 빌드 로그와 각 초기 실행 로그는 작업 폴더의 산출물에 별도로 보관했다. 빌드 과정에서 자동으로 변경된 기존 프로젝트 설정은 원복했고, 빌드 스크립트와 이 문서만 추가했다. 커밋·푸시와 외부 배포는 하지 않았다.
