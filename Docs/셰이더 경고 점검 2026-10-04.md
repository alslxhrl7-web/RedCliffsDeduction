## 실제 컴파일 오류

이전 배포 실행의 LensFlareDataDriven·CameraMotionVectors ‘GPU 미지원’ 메시지를 빌드 로그와 대조했다. 빌드 시 `Packages/com.unity.render-pipelines.universal-config/Runtime/ShaderConfig.cs.hlsl`을 찾지 못한 컴파일 오류가 있었다. GPU는 RTX 3060 Laptop이며, 포함 파일 자체와 현재 UPM의 패키지 경로는 정상적으로 존재했다. 오류의 HLSL 위치에는 현재 프로젝트가 아닌 `/Users/나민재/Documents/RedCliffsDeduction/...` 경로가 남아 있었다.

대상 셰이더, 공유 ShaderLibrary, config 파일을 재가져오고 셰이더별 컴파일 캐시를 초기화했지만 오류가 남았다. 기존 Library 상태에서 CleanBuildCache 빌드를 시도하자 Lit·ClusterDeferred 등까지 포함 파일 오류가 잡혔고, 오류 10건·경고 19건으로 빌드가 실패했다. 따라서 이전 실행에서 화면이 보였다는 사실만으로 전체 셰이더가 정상이라고 판단할 수 없었다.

장면·프로젝트를 저장하고 편집기를 정상 종료한 뒤 기존 Library를 `Logs/ShaderAudit/Library-before-reimport`로 이동해 보존했다. 패키지 소스 캐시 PackageCache는 새 Library에 재사용하고, 나머지 가져오기 캐시는 현재 프로젝트에서 재생성했다. 다른 프로젝트를 열거나 코드·장면·사용자 조사 저장을 삭제하지 않았다.

재생성 후 11:23:50 검사에서 Lit, CameraMotionVectors, LensFlareDataDriven, GaussianDepthOfField, BokehDepthOfField, PaniniProjection, TerrainDetailLit, WavingGrassBillboard 모두 지원 상태이며 ShaderUtil 오류·경고 메시지가 없었다. 이 결과는 이전 위치를 포함한 캐시 문제라는 설명을 뒷받침한다.

## 사용하지 않는 후처리 경고

조사 카메라는 `m_RenderPostProcessing: 0`이다. 기본 프로필의 DepthOfField 모드는 Off, Panini 거리는 0이며 빌드에서 미사용 후처리 변형을 제거한다. URP의 `PostProcessUtils.LoadShader`는 제거된 셰이더를 초기화할 때에도 ‘미지원 또는 stripped’ 경고를 기록할 수 있다. 이는 실제 포함 파일 컴파일 오류와 구분해야 한다. 경고를 숨기기 위해 모든 미사용 셰이더를 강제 포함하거나 패키지 코드를 수정하지 않았다.

## 그림자 경고

추가 광원 그림자 아틀라스는 2048×2048이며 이전 실행에서 18개 그림자 맵을 넣기 위해 해상도를 4분의 1로 줄였다는 메시지가 있다. 포인트 광원 하나는 여러 방향의 그림자 맵을 사용하므로 광원 개수와 맵 개수는 다르다. 이 경고는 자동 품질 조절이며 컴파일 실패와 별개다. 이번 점검에서는 조명 배치·그림자 품질·메모리 사용을 바꾸지 않았다.

## 도구와 기록

편집기 메뉴 `적벽추리 → 렌더링 검증`에 셰이더 상태 검사와 검증 빌드 도구를 남겼다. 상태 및 최종 빌드 결과는 `Logs/ShaderAudit`에 저장한다. Unity 종료 시 Temp가 제거되므로 영구 기록과 Library 백업은 Temp에 두지 않는다.
