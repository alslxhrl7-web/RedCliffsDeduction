## 제작 순서

1. 현재 씬의 배치·높이·대화/조사 연결과 보정 전 화면을 기록한다.
2. Blender에서 비율, 손가락 등 형상 오류, 접촉면, 법선과 UV를 수정한다. 고해상도 원본과 게임용 메시가 다르면 따로 보존한다.
3. 부품별 이름과 컬렉션을 유지한다. 원본은 편집 가능하게 두고 게임용 메시만 필요에 따라 합친다. 인물은 리그·스킨·동작 연결과 얼굴/손의 변형을 검사한다.
4. UV 겹침과 패딩을 확인하고 표면 정보를 베이킹한다. 색상은 조명 없는 Base Color, 노멀은 탄젠트 방식, AO는 약한 접촉 음영으로 사용한다. 금속과 거칠기는 재질별로 구분한다. URP의 금속 맵 R과 매끄러움 A에 맞춰 변환하며 매끄러움은 1−거칠기다.
5. Unity에는 실제 사용하는 UV가 첫 채널에 오도록 내보낸다. Base Color는 sRGB, 데이터 맵은 선형, 노멀은 Normal Map으로 가져온다. 밉맵·압축·크기는 화면 점유율에 맞추며 모든 자산을 무조건 4K로 만들지 않는다.
6. 기존 `.meta`와 GUID, 조사·대화 객체, 충돌체를 유지하며 시각 자산을 교체한다. 일반 조명과 대화 조명, 플레이어 눈높이·근접 화면을 확인한다. 인물은 대기·대화 동작 중에도 확인한다.
7. 변경 범위에 맞는 검사를 실행하고 결과·미완료 사항을 기록한다. 외형만 바뀐 경우 자산 연결과 화면 검사를 우선하고, 진행·저장 코드를 바꾸거나 연결에 우려가 있을 때 관련 회귀 검사를 실행한다.

베이킹은 모델 오류를 감추는 대체 수단이 아니다. 인물의 고정 조명/그림자를 색상에 구우면 이동과 조명 변화에 부자연스러워질 수 있으므로 표면 정보와 씬 조명을 구분한다. 재질 특성상 필요 없는 맵은 기록 후 생략한다.

## 커밋 전 확인

- 현재 PC에는 `Tools/check-staged-files.sh`를 실행하는 pre-commit 검사를 설치했다. Blender 자동 백업, 캐시, 검사 로그, 책상 미리보기 이미지와 Unity `.meta`가 함께 준비되지 않은 에셋은 커밋을 중단한다. 기존 Git LFS 훅은 유지한다.
- 다른 PC에서는 프로젝트 루트에서 `powershell -File Tools/install-commit-check.ps1`를 한 번 실행한다. 기존 pre-commit이 있으면 덮어쓰지 않고 중단하므로 검사 호출을 직접 합친다. 로컬 훅은 GitHub 서버 정책이 아니며 우회할 수 있다.
- 검사는 파일 구성을 확인한다. 미완성 코드나 시각 품질을 자동 판정하지 않는다. 실제 Play 검사와 화면 검토를 마친 변경만 선택해 커밋한다. 편집 원본·재현 스크립트·베이킹 보고서는 유지보수에 필요하므로 최종 게임 자산과 함께 보관한다.
- 대기 모션 검사는 격리된 테스트 저장 경로로 Play를 시작한 뒤 `Tools/Character Motion/Run Live Idle Checks`로 실행한다. `Logs/LiveIdle/checks.txt`의 COMPLETE와 인물별 결과를 확인하고 Play를 종료한다. 이 검사는 실제 LateUpdate를 측정하지만 키보드 수동 조작 검사를 대신하지 않는다.
