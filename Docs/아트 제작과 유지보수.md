# 소품·인물 제작과 유지보수

2026-10-13 사용자 결정: 소품과 인물은 베이킹을 거쳐 제작하고, 이후 수정하기 쉬운 원본과 절차를 함께 유지한다.

## 제작 순서

1. 현재 씬의 배치·높이·대화/조사 연결과 보정 전 화면을 기록한다.
2. Blender에서 비율, 손가락 등 형상 오류, 접촉면, 법선과 UV를 수정한다. 고해상도 원본과 게임용 메시가 다르면 따로 보존한다.
3. 부품별 이름과 컬렉션을 유지한다. 원본은 편집 가능하게 두고 게임용 메시만 필요에 따라 합친다. 인물은 리그·스킨·동작 연결과 얼굴/손의 변형을 검사한다.
4. UV 겹침과 패딩을 확인하고 표면 정보를 베이킹한다. 색상은 조명 없는 Base Color, 노멀은 탄젠트 방식, AO는 약한 접촉 음영으로 사용한다. 금속과 거칠기는 재질별로 구분한다. URP의 금속 맵 R과 매끄러움 A에 맞춰 변환하며 매끄러움은 1−거칠기다.
5. Unity에는 실제 사용하는 UV가 첫 채널에 오도록 내보낸다. Base Color는 sRGB, 데이터 맵은 선형, 노멀은 Normal Map으로 가져온다. 밉맵·압축·크기는 화면 점유율에 맞추며 모든 자산을 무조건 4K로 만들지 않는다.
6. 기존 `.meta`와 GUID, 조사·대화 객체, 충돌체를 유지하며 시각 자산을 교체한다. 일반 조명과 대화 조명, 플레이어 눈높이·근접 화면을 확인한다. 인물은 대기·대화 동작 중에도 확인한다.
7. 변경 범위에 맞는 검사를 실행하고 결과·미완료 사항을 기록한다. 외형만 바뀐 경우 자산 연결과 화면 검사를 우선하고, 진행·저장 코드를 바꾸거나 연결에 우려가 있을 때 관련 회귀 검사를 실행한다.

베이킹은 모델 오류를 감추는 대체 수단이 아니다. 인물의 고정 조명/그림자를 색상에 구우면 이동과 조명 변화에 부자연스러워질 수 있으므로 표면 정보와 씬 조명을 구분한다. 재질 특성상 필요 없는 맵은 기록 후 생략한다.

## 자산마다 남길 정보

| 항목 | 기록할 내용 |
|---|---|
| 원본 | `.blend` 위치, 편집용 컬렉션, 생성 원본과 라이선스 |
| 재작업 | 스크립트 또는 수작업 절차, 실행 조건, 덮어쓰는 파일 |
| 베이킹 | 맵 종류, 해상도, 색 공간, UV 채널, 패딩, 사용 엔진 |
| Unity | FBX·텍스처·재질 경로와 씬/프리팹 적용 대상 |
| 검증 | 메시/재질 수, 삼각형 수, 전후 화면, 검사 시각과 결과 |

원본과 출력은 각각 `ArtSource/<작업>/`, `Assets/Art/<분류>/<자산>/`에 둔다. 생성 파일을 수동 편집한 경우 생성 스크립트 재실행으로 유지되는 수정인지 명시한다. 경로는 프로젝트 기준 상대 경로를 사용한다. 한 번 더 실행해서 오브젝트가 늘어나지 않도록 갱신하거나 명확히 중단하도록 한다.

## 조조 책상 재작업

- 제작 원본: `ArtSource/CommandDesk20261013/CommandDesk_Baked.blend`
- 재현 도구: 같은 폴더의 `build_desk.py`; Blender 5.2.2에서 실행한다.
- 편집용 부품: `EditableDeskParts` 컬렉션. 기본 숨김 상태이며 편집할 때만 켠다. 합친 `CommandDeskBaked`와 동시에 렌더하지 않는다.
- Unity 출력: `Assets/Art/Props/CommandDeskBaked/CommandDeskBaked.fbx`, `Desk_*.png`, `DeskSurface.mat`
- 씬 연결: `Investigation` 씬의 `BakedCommandDesk`. 처음 설치는 `Tools → Command Desk → Apply Baked Desk`, 이후 파일 갱신은 `Assets → Refresh` 후 `Tools → Command Desk → Validate`를 실행한다. 설치 메뉴는 중복 설치를 거부한다.
- 생성 도구는 기존 `.blend`가 있으면 기본적으로 중단한다. 수작업 원본을 별도 저장한 뒤 의도적으로 재생성할 때만 `blender --background --python ArtSource/CommandDesk20261013/build_desk.py -- --replace-generated`를 프로젝트 루트에서 실행한다. Blender 실행 파일 경로는 설치 위치에 맞춘다. 이 경우 FBX·텍스처·완성 `.blend`를 덮어쓴다. 재현 가능한 변경은 스크립트에 반영하고, 수작업 변경은 원본 부품에서 게임용 메시를 다시 합치고 UV·베이킹·내보내기를 수행한다. 스크립트가 수작업 변경을 자동 반영하지는 않는다.
- 원본 질감은 기존 `Wood049` CC0와 자체 지도 그림이다. 베이킹 설정과 메시 통계는 `bake-report.json`, 검증 화면은 `Logs/CommandDeskBaked/`에 남긴다. Logs는 로컬 검토 자료이며 Git에 포함하지 않는다.

## 커밋 전 확인

- 현재 PC에는 `Tools/check-staged-files.sh`를 실행하는 pre-commit 검사를 설치했다. Blender 자동 백업, 캐시, 검사 로그, 책상 미리보기 이미지와 Unity `.meta`가 함께 준비되지 않은 에셋은 커밋을 중단한다. 기존 Git LFS 훅은 유지한다.
- 다른 PC에서는 프로젝트 루트에서 `powershell -File Tools/install-commit-check.ps1`를 한 번 실행한다. 기존 pre-commit이 있으면 덮어쓰지 않고 중단하므로 검사 호출을 직접 합친다. 로컬 훅은 GitHub 서버 정책이 아니며 우회할 수 있다.
- 검사는 파일 구성을 확인한다. 미완성 코드나 시각 품질을 자동 판정하지 않는다. 실제 Play 검사와 화면 검토를 마친 변경만 선택해 커밋한다. 편집 원본·재현 스크립트·베이킹 보고서는 유지보수에 필요하므로 최종 게임 자산과 함께 보관한다.
- 대기 모션 검사는 격리된 테스트 저장 경로로 Play를 시작한 뒤 `Tools/Character Motion/Run Live Idle Checks`로 실행한다. `Logs/LiveIdle/checks.txt`의 COMPLETE와 인물별 결과를 확인하고 Play를 종료한다. 이 검사는 실제 LateUpdate를 측정하지만 키보드 수동 조작 검사를 대신하지 않는다.

## 기존 자산의 적용 상태

현재 책상은 4종 맵의 베이킹과 Unity 연결이 확인됐다. 기존 인물·다른 소품은 개별 확인 없이 이 상태를 소급 적용하지 않는다. 이후 해당 자산을 수정할 때 위 절차를 따른다.

최근 인물의 `ArtSource/CharacterRepair20261012` 및 `ArtSource/ConversationMotions20261012`는 기존 결정에 따라 Git 제외 대상이다. 다른 PC에서 편집하려면 원본도 별도로 전달해야 한다. Unity용 출력만으로 Blender 원본까지 복원 가능하다고 기록하지 않는다.
