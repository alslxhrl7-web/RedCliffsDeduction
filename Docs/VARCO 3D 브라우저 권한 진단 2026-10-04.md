# VARCO 3D 브라우저 권한 진단 — 2026-10-04

## 확인된 원인

전역 사이트 설정은 허용이지만, 현재 대화에 저장된 사이트 거부 기록이 우선 적용되고 있다.

- `C:/Users/나민재/.codex/config.toml`: `[browser_use.origins."https://3d.varco.ai"]`의 `access = "allow"`.
- `C:/Users/나민재/.codex/browser/config.toml`: `[origins]`의 `allowed`에 `https://3d.varco.ai`가 있으며 `denied = []`.
- `C:/Users/나민재/.codex/browser/sessions/01a10217-f98e-7072-b7ef-2594e06dbc28.toml`: `[origins]`의 `denied`에 `https://3d.varco.ai`가 남아 있음.

설치된 브라우저 서비스의 `maybeAutoAnswerBrowserUseRequest`는 대화별 `denied` 항목이 일치하면 전역 허용보다 먼저 `decision: "deny", scope: "conversation", source: "browser-use-persisted-state"`를 반환한다.
이 분기는 `persisted_user_denied` 오류로 변환되며, 실제 도구 응답인 `A saved user permission setting blocks this action.`과 일치한다.

## 의미

- 사용자가 설정 화면에서 사이트 허용을 잘못 누른 문제가 아니다.
- 전역 허용을 바꾸거나 앱을 재시작해도 대화별 파일의 거부 기록은 남아 있다.
- 이번 오류는 사이트 안전성 판정, VARCO 서버 오류 또는 자동 심사 거부를 가리키지 않는다.
- 일반 사이트 조작을 위해 업로드·CDP 권한을 확대할 필요는 없었다. 이전 안내에서 이 권한을 변경하도록 유도한 것은 원인에 맞지 않았다.

## 해결 방향과 현재 제한

필요한 조치는 현재 대화에 저장된 VARCO 3D 거부를 사용자가 정상적인 권한 관리 절차로 해제하는 것이다. 전역 허용을 다시 누르거나 모든 사이트·데이터를 초기화하는 조치는 원인에 맞지 않는다.

현재 제공된 도구에는 대화별 거부를 해제하는 권한 관리 기능이 없다. 브라우저 보안 도구가 우회를 금지하므로, 진단 과정에서 권한 파일을 수정하거나 다른 브라우저로 우회하지 않았다. 권한 UI에서 대화별 해제가 지원되지 않으면 해당 저장 기록과 오류를 앱 지원에 전달해 해제 방법을 확인해야 한다.

사용자가 새 Codex 대화에서 같은 브라우저 작업을 요청하고 접근을 새로 승인하는 것이 대화 범위의 거부와 맞는 정상적인 재승인 방법이다. [공식 브라우저 확장 문제 해결](https://learn.chatgpt.com/docs/chrome-extension)도 새 대화가 대화별 연결 상태를 해소할 수 있다고 안내한다. 다만 해당 문서는 확장 브라우저 대상이며, 이번 내장 브라우저 문제가 실제 해결되는지는 새 대화에서 확인해야 한다. 현재 대화를 그대로 복구해야 하거나 새 대화에서도 문제가 재현되면 `/feedback`에 위 설정 충돌 증거를 전달한다.

설정 화면이 왜 전역 허용만 표시하고 대화별 거부를 함께 해제하지 않는지에 대한 제품 설계 또는 버그 여부는 미확인이다. 모델 생성과 Unity 인물 적용은 아직 시작하지 않았다.
